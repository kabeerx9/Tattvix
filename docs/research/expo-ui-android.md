# Expo UI (`@expo/ui`) on Android for SDK 58: coverage, styling limits, recommendation

Research date: 2026-10-25. Resolves GitHub issue #48. Context: `apps/native` is on SDK 57 / RN 0.86 and is about to move to SDK 58; Android is the primary target. The visual language is `docs/adr/0003-host-shell-and-accent-restraint.md`: white canvas, warm greys, one rose accent `#d70f58` on the primary button, active tab indicator, focus, links and selected pills only; neutral line icons; light only. The decision from #46 stands: use Expo UI only where it is stable on Android AND can be styled toward that look; otherwise RN primitives + StyleSheet + Reanimated.

"Read" means I read the primary text (package source, changelog, docs page, GitHub issue) myself. Anything I could not confirm is marked **unverified**.

## 1. Bottom line

1. `@expo/ui` is a regular SDK package in 58 (`~58.0.22` in `bundledNativeModules.json`, latest `58.0.23`), ships on Android via Jetpack Compose + Material 3, is "Included in Expo Go", and carries **no alpha/beta label on any docs page I read** ([DOCS], [BNM]). It is still moving fast: 23 patch releases between 2026-09-10 and 2026-10-25, most of them Android touch/layout fixes ([PKG] CHANGELOG).
2. There are three tiers ([PKG] README): `@expo/ui/jetpack-compose` (1:1 Compose API, Android only), `@expo/ui` universal (one tree for Android/iOS/web, thin wrappers over the platform tier), and `@expo/ui/community/*` drop-ins for `@gorhom/bottom-sheet`, `@react-native-community/datetimepicker`, `@react-native-menu/menu`, `@react-native-picker/picker`, `@react-native-segmented-control/segmented-control`, etc.
3. Every Compose component sits inside a `Host`. Flexbox stops at the `Host`; inside it you lay out with `Row`/`Column` and Compose modifiers, and RN children are re-hosted through `RNHostView` ([DOCS] ui/, host/). That boundary is where most open Android bugs live (section 4).
4. Styling: every Compose control exposes Material 3 `colors` slots, and `Host` takes `colorScheme`, `seedColor` and (since 58.0.22) `colorOverrides` to replace individual M3 roles ([PKG] `src/jetpack-compose/Host/index.tsx`). So the rose-on-neutral palette *can* be reached for colour. What cannot be changed is **shape and metrics** for controls without a `shape` prop (Switch, SegmentedButton, ModalBottomSheet, DatePicker), and the 48dp minimum touch target unless wrapped in `CompositionLocalProvider` ([PKG] CHANGELOG 58.0.22). Those controls will look Material even in our colours.
5. The universal tier removes most styling: universal `Switch` has no `colors`, universal `Button` has `filled | outlined | text` plus a small `style` subset, universal `Picker` is an M3 `ExposedDropdownMenuBox` with no colour props ([PKG] `src/universal/*/types.ts`). If we use Expo UI at all on Android, use the `jetpack-compose` entry point directly.

## 2. Component table (Android, SDK 58, `@expo/ui` 58.0.23)

"Status" is what the changelog, source and open issues show on 2026-10-25, not a vendor label (Expo publishes none). "Stable" = exists since ≤SDK 56 and the 58.x patch stream has only minor fixes; "Settling" = several Android fixes landed in 58.x or an open issue affects it; "New" = added in 58.

Without `seedColor` the palette **follows the device wallpaper on Android 12+ (Material You)** ([DOCS] host/), so a Host must always set `seedColor` or `colorOverrides` or our greys will be tinted per device. `colorOverrides` replaces individual roles (`primary`, `surface`, `outline`, …) with `#RRGGBBAA` ([PKG] Host `normalizeColorOverrides`). Yoga does not apply inside. | **Use only as the boundary for the controls below.** One `Host` per control, `colorScheme="light"`, `colorOverrides` with our tokens (`primary: #d70f58`, `onPrimary: #fff`, `surface: #fff`, `onSurface: #222`, `onSurfaceVariant: #6a6a6a`, `outline: #dddddd`). Set `color: #d70f58`, `elementColors.selectedDayContainerColor: #d70f58`, `containerColor: #fff`, `showVariantToggle={false}`. Skip the inline `DateTimePicker` (fills the Host and brings the M3 title/headline). |

## 3. Install and config for SDK 58

Verified against [PKG] `package.json`, `README.md`, `expo-module.config.json`, `android/build.gradle`, `plugin/src/babel-plugin.ts`; [BNM]; [NEWARCH]; [TPL]; [GRADLE]; [CL58].

1. **Upgrade the app first** ([CL58]):
   ```sh
   cd apps/native
   npx expo install expo@^58.0.0 --fix
   npx expo-doctor@latest
   ```
   SDK 58 = React Native 0.88.0, React 19.3.0 ([TPL] package.json; [CL58]). RN 0.87 made the Strict TypeScript API the default (deep `react-native/Libraries/*` imports become type errors) and removed `InteractionManager` ([CL58]). Reanimated bundled version is 4.7.1 with `react-native-worklets` 0.13.0 ([BNM]); `@expo/ui` declares `react-native-worklets` as a peer dependency ([PKG] package.json), which the app already has.
2. **Install the package** ([PKG] README; [DOCS] ui/):
   ```sh
   npx expo install @expo/ui
   ```
   This resolves to `~58.0.22` ([BNM]); run `npx expo install @expo/ui@58.0.23` if the latest patch is wanted (58.0.23 has the `TextInput` remount crash fix). `expo install` is the correct command because the package is version-locked to the SDK.
3. **Config plugin: none.** `expo-module.config.json` registers `expo.modules.ui.ExpoUIModule` with `coreFeatures: ["swiftui", "compose"]`; autolinking does the rest, and the README says "Configure for Android: No additional setup necessary" ([PKG]). Nothing goes in `app.json` `plugins`. The only plugin in the tarball is a **Babel plugin** (`@expo/ui/plugin` → `plugin/src/babel-plugin.ts`) that rewrites `Icon.select({ ios, android })` per platform; it is only needed if we use Expo UI's `Icon` with platform-split assets, which we will not (Lucide stays). **Unverified**: whether `babel-preset-expo` in SDK 58 enables that Babel plugin automatically; I did not find a statement either way.
4. **New Architecture: mandatory, nothing to set.** "SDK 55 and later run entirely on the New Architecture" and `newArchEnabled` is ignored ([NEWARCH]); the SDK 58 template ships `newArchEnabled=true`, `hermesEnabled=true`, `edgeToEdgeEnabled=true`, `android.enableMinifyInReleaseBuilds=true` ([TPL] gradle.properties). The app is already on SDK 57 so it is already new-arch only; remove any stale `newArchEnabled` key if one exists (none in `apps/native/app.json` today).
5. **Android SDK levels** ([GRADLE] lines 205-207; [TPL]): Expo's root-project plugin defaults are **minSdk 24, compileSdk 37, targetSdk 36, Kotlin 2.2.0** (`KotlinVersions.kt`). `@expo/ui` 58.0.23 compiles against **Compose UI/Foundation 1.12.1 and Material 3 1.5.0-beta01** plus `com.google.android.material:material:1.13.0`, and applies the `org.jetbrains.kotlin.plugin.compose` Gradle plugin at the project's `kotlinVersion` ([PKG] android/build.gradle). Material 3 1.5.0-beta01 was released 2026-10-07 ([M3]). The 57.0.5 changelog notes a fix for crashes on Android 7 (API 24/25) where `Color` props had no converter, so API 24 is the practical floor and matches Expo's default ([PKG] CHANGELOG, #47575). **Unverified**: the exact minSdk Compose 1.12 / M3 1.5 require; the androidx release notes I could read did not state one. Because the app's minSdk is Expo's default 24, no `expo-build-properties` change is required for Expo UI.
6. **Compose version conflicts**: open issue **#50050** reports that `@expo/ui` hard-pins a Material 3 version and conflicts with other Compose-based native modules (`NoSuchMethodError: ExposedDropdownMenuBox`). The pin moved to `1.5.0-beta01` in 58.0.17 ([PKG] CHANGELOG), but the issue is still open. `apps/native` has no other Compose module today (Clerk, Reanimated, Screens, SVG are not Compose), so this is a watch item, not a blocker.
7. **Expo Go / dev client**: docs headers mark `@expo/ui` as "Included in Expo Go" for SDK 58 ([DOCS] ui/, switch/). The new Expo Go supports only SDK 58 ([CL58]). The app uses `expo-dev-client`; a fresh development build is required after the upgrade in any case ([CL58]).
8. **Usage pattern** ([DOCS] ui/, host/; [PKG] Host source):
   ```tsx
   import { Host, Switch } from '@expo/ui/jetpack-compose';

   const colorOverrides = {
     primary: '#d70f58', onPrimary: '#ffffff',
     surface: '#ffffff', onSurface: '#222222',
     onSurfaceVariant: '#6a6a6a', outline: '#dddddd',
   };

   <Host matchContents colorScheme="light" colorOverrides={colorOverrides}>
     <Switch value={on} onCheckedChange={setOn}
       colors={{ checkedTrackColor: '#222222', checkedThumbColor: '#ffffff',
                 uncheckedTrackColor: '#ffffff', uncheckedBorderColor: '#dddddd',
                 uncheckedThumbColor: '#717171' }} />
   </Host>
   ```
   Always pass `colorScheme="light"` (ADR 0003 is light-only) and `colorOverrides`/`seedColor`, otherwise Android 12+ tints the palette from the wallpaper ([DOCS] host/).

## 4. Android stability notes that drove the recommendation

- The 57.x-58.x patch stream is dominated by the **RN-inside-Compose boundary** (`RNHostView`): hosted `Pressable` dropping presses on finger movement (#48217 in 57.0.7, #48970 in 58.0.0), no touches inside `AlertDialog`/`DropdownMenu`/`TooltipBox` (#48970), ripple stealing touch targets (#51237), stale child after `key` remount (#51914), `matchContents` + Reanimated measure crash (#49933), keyboard pushing sheet content off-screen (#49427) ([PKG] CHANGELOG, 57.0.5-58.0.23).
- **Open on 2026-10-25** (all Android, read on GitHub):
  - #52196 (2026-10-24, SDK 58): `RNHostView` consumes every tap, so a parent Compose `clickable` never fires when the tap lands on hosted content. https://github.com/expo/expo/issues/52196
  - #52066 (2026-10-22, 58.0.21): an `@expo/ui` control inside a RN `Pressable` loses a finger's tap. https://github.com/expo/expo/issues/52066
  - #52091 (2026-10-22): community `BottomSheetModal` never presents when its row is at the top edge of a `FlatList`. https://github.com/expo/expo/issues/52091
  - #50655 (2026-09-25): community `MenuView` popup content invisible after keyboard dismissal. https://github.com/expo/expo/issues/50655
  - #50050 (2026-09-11): Material 3 version pin conflicts with other Compose modules. https://github.com/expo/expo/issues/50050
- Pattern: **leaf controls that own their whole Host are fine; anything that nests RN content inside Compose (sheets, menus, dialogs with RN bodies) or Compose content inside RN pressables is where regressions keep appearing.** The table follows that line.

## 5. Recommendation

Adopt `@expo/ui` on Android in SDK 58 for exactly two leaf controls, imported from `@expo/ui/jetpack-compose` and each wrapped in its own `Host matchContents colorScheme="light"` with `colorOverrides` set to the ADR 0003 tokens (never rely on the default palette, which follows the device wallpaper on Android 12+): the `Switch` (foreground-coloured when on, per the ADR) and the `DatePickerDialog`/`TimePickerDialog` for stay dates (rose selection, white container, variant toggle hidden). Build everything else with RN primitives + StyleSheet + Reanimated: primary button, text fields, segmented pills, bottom sheets, menus and progress. Those controls either cannot drop their Material 3 shapes (segmented row, sheet radius, 48dp targets), duplicate motion and tokens we already own on web, or route RN content through `RNHostView`, which is where the still-open Android touch bugs (#52066, #52196, #52091, #50655) live. Install is `npx expo install @expo/ui` after `npx expo install expo@^58.0.0 --fix`; there is no config plugin, the New Architecture is already mandatory, and Expo's default minSdk 24 / Kotlin 2.2.0 satisfy the package's Compose 1.12.1 / Material 3 1.5.0-beta01 build. Keep #50050 (Compose version pin) and #52066 (control inside `Pressable`) on a watch list and re-evaluate the sheet and menu rows when they close.
